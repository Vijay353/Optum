## Top limitations and production gaps

1. No real EHR/payer/HIE connectivity; FHIR shapes are approximations without profile validation.
2. Demo identity and static tokens — production needs SSO/RBAC, SMART Backend Services, per-system credentials and secret management.
3. The default extractor only understands the synthetic document format; real documents (scans, varied templates) need OCR plus a validated model with an evaluation set.
4. Single process and one SQLite file; production needs independent services, an outbox/queue for events, retries with dead-lettering and monitoring.
5. Task routing to a real EHR work queue, reviewer actions after the Task (accept/reject evidence, request records) and packet assembly are out of scope.
6. Retention, access audit export, minimum-necessary review and BAA/legal review are documented but not implemented.
7. No user research has been run; all hypotheses in spec §6 remain open.
